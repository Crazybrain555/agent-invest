# 第 I 部分 L1 整体规划

## I.1 L1 的定位与边界(协议 §3.1 / §3.4 / §3.5)

L1 回答:这条资料/数据/工具结果来自哪里?什么时候、用什么 adapter / query / parser 取得?
现在是什么可消费形态?追溯等级、质量状态和下游契约是什么?

L1 不回答:这是不是高价值投资信息?支持哪个假设?与历史证据是否冲突?应不应该采信?

**L1 有自己的"筛选处理清洗",与 L2 的筛选是两段不同的活:**

```text
L1 载体规范化(carrier normalization,§3.5)——处理结构与载体,不碰投资语义:
  解析(PDF / Word / PPT / 图片 OCR / 录音转写 / Excel)
  → 按业务结构切分(段落 / 表格 / Q&A;不按版面和 token 切)
  → 表头 / 单位 / 脚注保留,Q&A 问答绑定
  → heading_path / order_index / semantic_key / content_hash 生成
  → 稳定噪声处理(页眉页脚 / 页码 / 水印 / 控制字符)
  → raw 保真留存 + quality_status 标注(ok / needs_review / unusable / empty)
  结构化数据侧的同类活:字段契约核实(列名 / 单位 / 活表裁决)、类型规整、
  查空登记、幂等去重与取代——同样是"清洗",只是对象是 recordset 不是版面。

L2 证据化筛选(§4.5)——高价值选择性抽取、registry 归一、对账、冲突、采信。
```

一句话判别:**L1 负责让资产不孤立、可追溯、可消费;L2 负责理解资产在说什么。**

安全红线(§3.5):L1 不得因"像套话"删除可能含实质风险、业绩变化、会计政策、重大事项的
信息——可以标质量、可以不生成 unit,但原文与 parser artifact 必须保留、可重处理,
不得让下游永久不可见。

边界三条(§16.3 / 7 / 9):raw 止于 L1;"先轻后重"只指存储不指职责——解析 / OCR /
表格识别 / 上传件处理全是 L1 的活;L1 资产暂无消费方(L2 未立项)是协议分期常态,
资产照常沉淀。

## I.3 结构化数据路径:从"预注册"到"字典可见、受控取数"

v0.1 的隐含假设是"所有取数需求都能预先注册成 dataset"。这对订阅型主链(行情 / 财务 /
事件)成立,对 AI 的探索型需求不成立——课题、evidence_request、人工问题随时会要
"字典里有但没注册"的数据。修正为三条使用形态(Lane),同一账本、同一信封出口:

### I.3.1 Lane A:注册数据集(现状,主链)

适用:长期订阅、增量同步、将进 L2 numeric_observation 的数据(行情 / 三大表 / 指标 / 事件)。
纪律维持现状:dataset_key 语义契约(registry/datasets)+ provider catalog 物理契约
(registry/providers)+ registrar 幂等登记;每字段配 mapping / unit / fixture。

### I.3.2 Lane B:数据字典是一等对外资源(定案 = §II F14)

字典分两件,角色不同(2026-07-06 核对仓库实况后的准确表述):

- **契约件(已存在)**:`registry/providers/*.catalog.yaml`(wind 8 个已消费 table_alias +
  tushare 8 个 endpoint,含安全默认、单位注记、活表裁决)与 `registry/datasets/*.yaml`
  (4 条语义契约,列 / 单位 / fixture)。机器可读、Git 管理、实测核实;按 §II.9 定案
  **有意不收未消费表**(防幽灵条目)。
- **库存件(不存在——Lane B 的真正新建物)**:全库 inventory。RDS 50 表的表 / 列清单目前
  只在 §II.11 的文字附录里,不可机读。inventory 应由 prober 现场探测生成(日期戳快照;
  活库是唯一权威,§II.9 权威链),是探测产物不是契约,因此不违反"不登记幽灵条目"
  ——不进 catalog 正文,独立成件。

让 AI 看得到的形态:

- **近期**:一条 CLI 导出两件——契约件(export_contracts 已有,扩展)+ inventory 探测件
  (表 / 列清单、活表状态、新鲜度探测结论);
- **目标**(§3.11 MCP 映射):字典条目 = `resources/list`,内容 = `resources/read`,只读;
  写动作(登记、取数)一律建模为 tool;
- **纪律**:字典只描述"有什么、什么口径、怎么定位",不含凭证;契约件(实测核实)与
  inventory 探测件(存在性已探、语义未核)在字典里可区分——AI 用到"仅 inventory 可见"
  的表 / 列时,自己能看见"语义未核"的风险。

### I.3.3 Lane C:受控 ad-hoc 取数(定案 = §II F13)

AI(evidence_request 执行者 / 课题 / 人工指令)对"字典里有但没注册"的需求,允许在受控回路
内自主取数。协议依据:§8.6(evidence_request)、§10.2(L6 或人工发起数据需求 → L1 provider
adapter)、§6.5.1 规则 5(确需在线拉取走受控回路,产物仍先落 L1)。

**形态遵守协议原则 11"LLM 出候选,规则做裁决"与 F7 / F8**——AI 不在运行时写自由 SQL,
而是照着字典起草一份临时查询配置(候选),交确定性校验器裁决后执行:

```text
入口:evidence_request 或人工指令(source_policy 圈定 provider,budget 限轮次 / 费用)
起草:AI 读字典(Lane B)→ 起草临时查询模板(表 / 列 / 谓词 / 绑定参数——与 dataset YAML
      的 providers 段同构的轻量配置,不是自由 SQL 文本)
裁决:确定性 validator 按 F7 全套安全规则校验(白名单表列、绑定参数、required predicates、
      max_rows、timeout、deny tokens、禁 SELECT *、只读账号、varchar8 日期列禁 CONVERT)
      + F12 预检 fail-fast;不过即拒,报错列明缺什么
执行:经 asset_intake 的 adapter / CLI(未来 MCP tool),不是让 agent 拿凭证裸连
      ——查空、登记、审计自动发生;临时裸连只读库属调试行为,不产生可引用资产,
      任何要进系统的结果必须经登记入口
登记:结果照常登记 data_asset(asset_kind = dataset_snapshot, payload_kind = recordset),
      dataset_key 用保留命名空间 adhoc.<provider>.<slug>;provider / query_params /
      returned_fields / provider 侧 as-of / adapter 版本必填(§3.7)——可复查是底线;
      查空照记 source_access(§3.9);访问动作落 action_log
消费:adhoc 快照没有预注册字段契约,这是显式状态(不是缺陷伪装成正常);
      L2 消费前需字段映射确认——那是 L2 准入的事,L1 侧只保证登记完整
```

本 Lane 已定案为 §II **F13**(v1.3 新增):F7 安全规则全套沿用,F8"不是 text-to-SQL"
原则从已注册 dataset 推广到字典内未注册需求。若用户定稿改选其他自由度档位(§I.8 #2),
改 F13 一条即可。

禁止的仍然禁止(§16.24 / §16.31):不登记的旁路取数、拿 agent 总结当来源、绕过 L1 / L2
改预测。Lane C 不是放开自由取数,是把"AI 有别的需求"收进受控回路。

### I.3.4 晋升规则:复用即转正

need-to-register 纪律从"先注册才可用"调整为:**探索可先走 Lane C,复用需求转正为 Lane A**。
转正判据(满足其一):同一 adhoc 查询模式重复出现;需求进入 L5 数据订阅(§7.6);
需要 source_checkpoint 增量维护。转正动作 = 建 dataset yaml + catalog 补实测 + fixture;
历史 adhoc 快照不迁移,保持原样可追溯。

### I.3.5 provider 通道事实(2026-07-06 实测,详见 §II.11)

- **wind_rds**(阿里云 SQL Server,50 表子集):主通道。行情至上一交易日、预告至当天;
  批量 / 表宽占优;活表裁决与列名 / 单位全部实测入 catalog。
- **tushare_api**(HTTP,同事共享 token,将换密钥):备用 + 交叉校验。八个所需 endpoint
  当前 token 全通;限流按积分。

| 维度 | wind_rds(实测) | tushare_api(实测) | 同花顺 iFinD(候选,**未实测**) |
|---|---|---|---|
| 覆盖 | A股行情/财务/事件/指数/基金/HK 50 表 | 覆盖同类,接口粒度细 | 宣称全,未核 |
| 新鲜度 | 预告当天、行情 T-1 | 同级 | 未核 |
| 稳定性 | RDS 直连,受同事同步作业影响 | 官方 SaaS,受积分/频控 | 未核 |
| 限流 | 无(自律:白名单模板+行数上限) | 积分制,min_interval 300ms | 未核 |
| 凭证合规 | 同事账号,将轮换;只读 | 同事 token,将轮换 | 需自有账号,采购流程 |
| 接入成本 | catalog 已就绪,只差 adapter | 同左 | 全新 catalog + adapter |
| dataset_key 映射 | 四条首发全覆盖 | 四条首发全覆盖 | 待字典核实 |

结论维持 F11:wind 主、tushare 备;iFinD 仅在前两者不可持续时启动评估,不预投入。
同事的 tushare MCP 封装不作为接入通道(账本唯一:source_access + data_asset,不允许第二套
SQLite cache);其限流退避、错误分类、工具索引设计已吸收为 catalog 与 adapter 实现参考。

## I.4 横切职责(四条路径统一的 L1 全域纪律)

1. **登记与追溯**:source_ref 是 provenance 引用,可由视图 / endpoint 派生(§2.3);
   每次访问(含查空)落 source_access,错误≠查空(§3.9);凭证只走环境变量。
2. **幂等 / 版本 / 取代**:content_hash 判变;新版本取代不覆盖(superseded_by);
   append-only 是全系统一跳引用成立的前提(§12.3)。
3. **scope 继承承诺**(§3.6 / §16.10):public view 与 API 返回的每个 unit / snapshot 带全
   scope keys(company_ref / security_ref / report_period / material_type…);物理存储可范式化。
4. **Subject Registry 采集义务**(§6.5.1 规则 4 / 5):所有创建公司 / 证券侧信息的 L1
   producer 对 identifier scheme(lei / uscc / sec_cik / isin / exchange:ticker…)
   "有则必填";强键校验数据走本地快照,不在主链路实时调外部 identifier API。
   现状:披露侧已有 company_identifier 表(scheme 覆盖**未核**);intake 侧
   subject_candidates 是 subject_key 形态、尚无 identifier 采集。盘点列入缺口。
5. **change feed**(§2.8):每个 L1 服务对下游暴露同构 feed——outbox + change_events_v1
   视图 + `GET /v1/changes?after_seq` 目标端点;observed / materialized 两事件语义,
   下游失效只由 materialized 触发。disclosure_anchor 与 asset_intake 都需补齐端点与两语义。
6. **对外契约五件套**(§3.11):可寻址(asset:// URI)、读契约版本化(`*_v1`)、可检索

## II.1 定案清单

- **F1 dataset_key 语义命名,provider 无关;首发四条**:
  `cn_equity.eod_quote` / `cn_equity.fin_statement`(`statement=income|balance|cashflow`,
  **不含 indicator**)/ `cn_equity.fin_metric`(`metric_set=financial_indicator|...`)/
  `cn_equity.earnings_event`(`event_type=forecast|express`)。provider/通道只进 provenance。
- **F2 earnings_event 独立**(披露事件 ≠ 期间报表事实);**fin_metric 独立**(provider 指标
  ≠ 三大表原始事实,每条 record 带 `metric_origin=provider_derived|announced_by_company|
  wind_adjusted|ttm_mrq`,防 L2/L3 误当披露原始值对账)。
- **F3 复权口径**:L1 canonical 只存不复权 OHLCV + adj_factor(行级 row_published_at);
  qfq/hfq 为派生视图,`qfq(t;basis_date)=raw(t)×factor(t)/factor(basis_date)` 且
  `basis_date ≤ as_of`。字典级标注 `adjustment_factor_asof_grade: latest_recomputed`
  ——当前因子是"最新重算"性质,**禁止当作正式回测级 as-of-safe 结果**;将来接权益 PIT 数据后
  才允许升 `pit_safe`。实测硬事实:**adj_factor 是 provider 相对值**(同日 000001.SZ:
  Wind 85.33 vs tushare 139.008),跨 provider 绝对值不可比,只有比值有意义。
- **F4 两层配置**:
  `registry/datasets/<dataset_key>.yaml` = 语义契约(字段/单位/口径/时间语义/dedup 规则,
  小而稳定);
  `registry/providers/<provider>.catalog.yaml` = 物理世界(连接 profile 名、safety 默认、
  索引纪律、**table_alias:候选表 + activation 规则 + freshness 探测**,宽而 provider 专属)。
  dataset YAML 经 table_alias 引用 catalog,物理表改名/换代不动语义层。两者都是服务内
  Git 配置(协议 §3.7),pydantic 模型 + contract test 守护;只登记当前消费的字段。
- **F5 L1 不跨 provider 合并、不裁决**:同 dataset_key 多 provider 各自入账
  (`(provider, dedup_key)` 唯一,零改表);对账/采信在 L2。
- **F6 幂等三态**(§II.6):同 provider 同 semantic_key 同 content_hash → observed;
  content_hash 变 → materialized + supersede;不同 provider 永远独立。
- **F7 SQL 只走白名单模板**:绑定参数、allowed tables/columns、required predicates、
  max_rows、timeout、deny tokens、禁 SELECT *、只读账号;大表必须带证券代码前缀谓词;
  **日期列是 varchar(8),SQL 内禁止 CONVERT 破坏索引**,日期转换在 adapter 出口做;
  跨票篮子查询 `IN (:list)` 限 ≤200。
- **F8 LLM 不进登记层**:未来自由问数 = text-to-DatasetRequest(候选经 registry validator
  确定性裁决),不是 text-to-SQL;M-C 不实现。
- **F9 adapter 不碰 DB**:只返回 DatasetResult;registrar 是唯一写 DB 的地方。
- **F10 登记路径无字段投影**:按 registry 完整语义字段集落 payload;投影是读侧概念。
- **F11 provider_priority 是服务级配置,不进 dataset_key**:默认 A 股四条数据集均
  `[wind_rds, tushare_api]`(Wind SQL 主通道、tushare 备用/交叉校验;两通道均已实测可用,
  见 §II.11);用户改优先级 = 改一行配置。
- **F12 配置预检 fail-fast(用户 2026-07-06 追加拍板)**:换源的理想路径是"改几个配置参数
  就能用"——因此 adapter 启动/doctor 必须先跑**配置预检**:活源探测 active table/endpoint
  存在性、required_columns 齐全性、freshness;**缺必要表/列/端点 = 显式报错并列出缺什么**,
  绝不静默降级、绝不部分工作。预检通过才允许 fetch。未来非结构化源(web search / MCP / API)
  接入 tool_result 路径时沿用同一原则:source catalog 配置 + 预检 fail-fast,一切皆配置。
- **F13 临时查询模板快速通道(v1.3 新增,Lane C 定案,详见 §I.3.3)**:探索型需求可不经
  预注册 dataset——AI 依字典(F14)起草**临时查询模板**(与 dataset YAML providers 段同构
  的轻量配置,不是自由 SQL 文本),经确定性 validator 按 **F7 全套安全规则 + F12 预检**
  裁决后执行;结果必须登记 data_asset(dataset_snapshot),dataset_key 用保留命名空间
  `adhoc.<provider>.<slug>`,协议 §3.7 必填项照常,查空照记 source_access。
  **复用即转正**:同模式重复出现 / 进 L5 订阅 / 需 checkpoint 增量 → 转正为注册 dataset;
  历史 adhoc 快照不迁移。入口限 evidence_request / 人工指令(§16.31)。
- **F14 数据字典两件套(v1.3 新增,Lane B 定案,详见 §I.3.2)**:**契约件** = registry
  双层配置(已有;只登记消费项,防幽灵条目纪律不变);**库存件 inventory** = prober 现场
  探测生成的全库表 / 列 / 新鲜度**日期戳快照**(探测产物非契约,不进 catalog 正文)。
  两件经 CLI 导出(近期)/ MCP resources(目标,§3.11:资源只读、写走 tool)对 AI 可见;
  不含凭证;"仅 inventory 可见、契约未核"的项对 AI 显式可辨。

```python
    locator: str | None      # 含 table_alias 与实际 active 物理表;严禁 host/凭证
    raw_asset_ref: str | None = None
    scope: ScopeHints = ScopeHints()
    warnings: tuple[str, ...] = ()
    stats: dict[str, int] | None = None

class ProviderError(Exception): ...

class DatasetProvider(Protocol):
    provider_name: str
    adapter_name: str
    adapter_version: str
    source_tier: SourceTier   # 首发均 tier_1
    trace_level: TraceLevel   # G1
    def fetch(self, request: DatasetRequest) -> DatasetResult: ...
```

locator 形如 `wind_rds://alias/earnings_forecast?active_table=AShareProfitNoticeNew&template=...@v1&params_hash=...`。

  无 OPDATE 的表在 catalog 里声明 fallback 序,不写死代码。
- tushare_api:income/balancesheet/cashflow(实测可用,含 ann_date/f_ann_date/report_type/
  comp_type/update_flag;金额单位=元,无需换算)。

### II.5.3 cn_equity.fin_metric(v1.2 新增)

### II.5.4 cn_equity.earnings_event

- params:security 或 ann_date range、report_period?、event_type=forecast|express。
- **forecast**:wind_rds alias `earnings_forecast`,candidates=[AShareProfitNoticeNew(实测
  active:36.2 万行、数据到当天)、AShareProfitNotice(实测停 20240905,保留候选)];

  published_at(最新公告日)、first_ann_date、style(**归一枚举**:Wind 数字代码 454010000 系
  与 tushare 中文标签"预增/预减…"各配 code_map,原值保留 provider_raw)、sign_change、
  净利区间(万元→元)、同比幅度区间(%)、扣非净利区间与上年扣非、EPS 区间与上年 EPS、

- **express**:wind_rds `AShareProfitExpress`(实测活,全局 max ANN_DT=20260507,34 列:

  tushare express 实测可用,字段对应。
- 修正/多次预告 = 新行(公布次数 + 首次公告日),与 §II.6 supersede 语义对应。

## II.6 幂等、去重、取代与 as-of(同 v1.1,冻结)

semantic_key = dataset_key + 规范化 query scope → `semantic_key` 列;
dedup_key = sha256(semantic_key || content_hash) → `(provider, dedup_key)` 唯一;
observed / materialized + supersede 三态;content_hash 不含查询时间;
registry 版本不进 dedup_key(版本走 provenance);snapshot 级 published_at = 行级最大值;
(provider, semantic_key) active 部分索引随 P4 migration 加。

## II.7 安全与增量(v1.1 基础上强化)

- SQL:F7 全套 + varchar8 日期列禁 CONVERT + 篮子 ≤200 + 大表禁无证券码谓词的全市场扫
  (全市场增量需求走"按交易日 + 分块"模板,逐票或小篮子)。
- API:限流退避与错误映射;权限/频控 = `error`,真空 = `empty`,两者都不建 data_asset;
  **不引入 skill 的 SQLite cache/MCP 工具形态**(账本唯一)。
- 增量:行情按交易日历(AShareCalendar)驱动 security × trade_date 窗口;财务/事件按
  公告日(ANN_DT / ann_date)增量 + lookback 兜重述,不按 max(report_period);
  checkpoint 表进 roadmap,M-C 显式窗口。
