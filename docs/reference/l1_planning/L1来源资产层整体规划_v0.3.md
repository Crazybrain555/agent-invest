# 0. L1 层宪法

1. **L1 是来源资产层,不是事实层。**
   L1 的正式产出只有 `data_asset`,回答"资料从哪里来、何时取得、如何复查、现在是什么
   可消费形态、是否发生变化"。L1 不回答"是否高价值、是否采信、支持哪个预测假设"。
2. **所有来源一个信封。**
   PDF、结构化数据库、HTTP API、web / MCP 工具结果、人工上传件,统一落到
   `data_asset = identity + scope + time + provenance + payload + state`。差异进
   `asset_kind` / `payload_kind` / payload 与登记过的扩展字段,默认不新增顶层对象。
3. **raw 止于 L1,但 L1 不是全量 raw data lake。**
   披露 PDF 与人工上传原件自维护;标准数据库 / API / tool result 可以轻存储,只保存
   可消费 snapshot、访问记录、locator、provider_as_of、query_params 等追溯信息。
   **轻存储不等于轻职责,更不等于轻登记。**
4. **L1 做载体规范化,不做投资语义。**
   文档侧:解析、OCR、切分、表格结构保留、heading_path / order_index / content_hash;
   结构化侧:字段契约核实、类型规整、机械单位换算、查空、幂等、取代;上传侧:原件登记、
   转写 / OCR / Excel 区块结构化。L1 不做 claim 抽取、冲突裁决、采信、预测相关性判断;
   也不得因"像套话"删除可能含实质信息的内容(安全红线,协议 §3.5)。
5. **AI 可见的是目录与契约,不是裸库权限。**
   L1 必须让 AI / agent 看得到"有哪些来源、哪些数据集、哪些表 / endpoint / 字段、哪些
   已核实、哪些只是 inventory";但 AI 不能拿凭证裸连,也不能绕过登记路径。
6. **探索可以存在,但必须受控。**
   预注册数据集不是唯一入口。字典可见但未注册的数据,可经受控 ad-hoc 通道形成一次性
   `dataset_snapshot`;但 ad-hoc 不能长期滞留为稳定数据产品,**复用即转正**。
7. **append-only 是一跳追溯成立的前提。**
   data_asset、source_access、processing_run / action_log、change_event 都不原地改写事实;
   内容变化产生新资产或 supersede;正常消费只存一跳引用,全链由审计递归重建。
8. **LLM 出候选,规则做裁决。**
   LLM 可以起草查询需求、字段映射候选、material_type 候选、检索关键词、结构摘要;凡进入
   登记、准入、执行、字段契约、权限边界的地方,必须由确定性规则校验。LLM 不进登记层。
9. **账本唯一。**
   source_access + data_asset 是 L1 唯一账本;任何 adapter / skill / harness 不得自带
   第二套 cache 或私账(SQLite cache 之类一律不引入)。
10. **一切皆配置,代码只是解释器。**
    语义契约、物理映射、provider 优先级、候选表、安全规则全部是 Git 管理的数据(YAML);
    换通道、换表、换 provider 改配置不改代码、不改契约、不改下游;配置启用前预检
    fail-fast,缺什么显式报错列明,绝不静默降级。

# 1. 统一对象:data_asset

## 1.1 最小字段组

每个 L1 资产映射到六组字段(分组是叙述结构,契约约束只来自字段定义与必选性,协议 §2.1):

```text
identity     asset_id / asset_uri / asset_kind / payload_kind / contract_version
scope        subject_candidates / company_ref? / security_ref? / report_period? /
             material_type / title / heading_path / semantic_key / parent_ref / order_index
time         event_time / published_at / observed_at / provider_as_of
provenance   source_ref / source_access_ref / provider / adapter / tool / locator /
             raw_asset_ref / producer_action_ref / source_tier / trace_level
payload      text / table / qa / recordset / search_result / api_response /
             page_snippet / calculation_table / model_table / checklist / note
state        quality_status / content_hash / is_active / superseded_by / sensitivity
```

字段纪律:能列化、需检索、需过滤、需权限控制的字段进列;内容形态差异进 payload;
新增字段一律按协议 §2.1 扩展字段纪律登记。信封模型与 kind 矩阵由 `envelope_kernel`
共享包承载,服务内不得重复定义或私改;kind 矩阵变化经协议升版。

## 1.2 source_ref 与 locator

`source_ref` 是 provenance 引用,不是第二套来源对象;可由 public view / endpoint 派生
(协议 §2.3),语义必须稳定。`locator` 定位来源内部子位置:PDF 页 / 段、表格行列、
provider table_alias 与实际 active 物理表、API endpoint、web URL、tool result item id。
locator 严禁含 host / 凭证。

## 1.3 raw 与 payload

`payload` 是下游可消费内容;`raw_asset_ref` 是原始字节 / 原始响应的保真引用。披露 PDF 与
上传文件必须保留 raw;结构化数据与工具结果可不留完整 raw response,但**登记底线不降**:
payload snapshot、returned_fields、locator、source_access、provider_as_of、query_params
必须齐全——可复查是底线。

## 1.4 scope 两级承诺(canonical ref 不可伪造)

- **披露 document_unit**:company_ref / security_ref / report_period / filing_type /
  announcement_date 必须从 document 继承到 unit 级读契约(协议 §3.6 / §16.10)——物理存储
  可范式化,读契约必须反范式化。
- **dataset_snapshot / tool_result / artifact_unit**:`subject_candidates`(subject_key
  全形式,如 `security:000001.SZ`)是契约字段;canonical company_ref / security_ref 仅在
  Subject Registry 或服务内 crosswalk 可确证时列化,**未解析是显式状态,不得为"看起来
  完整"而伪造**。Subject Registry(协议 §6.5.1)就绪后按 identifier 强键升级解析。

# 2. asset_kind 分型

| asset_kind | payload_kind | 来源路径 | L1 最小职责 |
|---|---|---|---|
| `document_unit` | text / table / qa | disclosure_anchor、upload_service | 原文保真、业务结构切分、表格 / Q&A 完整保留、heading_path、locator、content_hash |
| `dataset_snapshot` | recordset | asset_intake、upload_service 数据摘录 | provider、dataset_key、query_params、returned_fields、provider_as_of、records / 摘要、契约状态 |
| `tool_result` | search_result / api_response / page_snippet | web / MCP / Claude / Codex / 插件 / 外部 API | tool / source、query、returned_items、每项 locator;agent 总结不得当来源 |
| `artifact_unit` | calculation_table / model_table / checklist / note | 人工上传、研究工件 | 上传人 / 作者、material_type、sensitivity、可复核性、原件 hash、区块 locator |

两条说明:**人工上传不是单独的 asset_kind**——上传只是入口,按内容形态进入四类之一;
**查空不是 asset_kind**——查空记录在 `source_access(result_status = empty)`,仅当回应
evidence_request 时才由 L2 生成 `null_observation`(协议 §3.9,不在两层重复建对象)。

# 3. L1 服务版图与拆分原则

```text
packages/envelope_kernel(已建)
  统一信封模型 / kind 矩阵 / asset:// URI / 契约 schema——跨服务共享核

services/disclosure_anchor(live)
  披露 PDF / 公告 / 财报硬锚路径:raw PDF + parser artifact + document_unit + change feed
  其手法是其余 L1 服务的复用蓝图(三 schema / *_v1 views / outbox / processing_run)

services/asset_intake(已建;真实 provider adapter 待接)
  结构化数据 dataset_snapshot + 轻载外部结果 tool_result
  四类配置件 + provider adapter + registrar(唯一写 DB)

services/upload_service(未来,独立服务——固定决策 D1)
  人工上传文件 / 文本 / 表格 / 图片 / 录音转写 / Excel / 模型工件
  raw 保真 + 载体规范化 + sensitivity + material_type 人声明
```

**服务拆分原则**:是否拆服务不按来源数量决定,而按**生命周期、权限边界、raw 处理形态**
决定。披露 PDF 是自维护硬锚,保留独立服务;人工上传涉及原件、OCR / 转写、敏感度与权限
隔离,独立成服务;结构化数据与轻载 tool_result 都是"访问外部源后登记 snapshot / item",
同属 asset_intake。所有服务必须复用同一信封核与同一 public contract 风格。

各服务现状缺口统一见 §17。

# 4. 统一入库生命周期

```text
source discovery / source policy
→ source_access:记录访问、查询参数、结果状态、provider_as_of、错误或查空
→ producer action:parser / adapter / tool harness / upload parser 的执行记录
  (processing_run,即 action_log 的 L1 特化)
→ data_asset:形成可寻址、可追溯、可消费资产(幂等判定 + supersede)
→ public view / API:按 *_v1 读契约暴露
→ change feed:observed / materialized 事件供 L2 / L6 消费
```

状态判别(全路径统一):

- `ok`:有结果并形成 data_asset;
- `empty`:查询成功但无结果——只记 source_access,不建 data_asset;
- `error`:权限、连接、限流、schema 不匹配、preflight 失败——**不得伪装成 empty**;
- `observed`:巡检过、内容未变(记 content_hash),不触发下游失效;
- `materialized`:新资产 / 内容变化 / 取代——**下游失效只由 materialized 触发**(协议 §2.8)。

# 5. 披露文件路径:disclosure_anchor

披露 PDF 是 L1 中最硬的自维护锚。职责不是"把 PDF 切成 chunk",而是把交易所披露文件转成
可复查、可增量感知、可由 L2 精选抽取的 document_unit。

硬规则:

1. **原文件不可变**:raw PDF、hash、provider document id、download / access 记录必须保存。
2. **按业务结构切**:标题、段落、完整表格、完整 Q&A、脚注、跨页表格保持逻辑完整;
   不得按 token 或版面碎切作为主契约。
3. **scope 继承**:document 级 company / security / report_period / filing_type /
   announcement_date 必须在 unit 级 public view 可检索(§1.4 第一级承诺)。
4. **不删实质信息**:风险提示、会计政策、重大事项、业绩变化不得因"像套话"永久不可见。
5. **蓝图地位**:其三 schema、public views、outbox、processing_run、source_ref、
   contract_version 是其他 L1 服务的复用蓝图(协议 §3.10)。

现存缺口(对照协议 §3.10 三点补强,不排时序):
**G1** `GET /v1/changes` 端点与 observed / materialized 两事件语义未落(outbox 表 +
change_events_v1 视图已落);**G2** envelope_kernel 反向接入(术语已收敛,信封 / URI /
kind 矩阵仍服务内自持,目标是用共享包契约测试替换重复定义、不改运行时行为);**G3** 跨路径
对账锚 (security, report_period) 两侧已就绪——对账是 L2 职责,L1 保证键可用,持续维持。

# 6. 结构化与工具源治理:asset_intake

## 6.1 四类配置件 + 一个登记器

```text
1. source / provider catalog   外部源:连接 profile 名、tier / trace、安全规则、rate limit、
                               freshness 探针、候选表 + activation 规则、preflight。凭证不入配置。
2. dataset contract            provider 无关的稳定语义数据集(如 cn_equity.fin_statement):
                               query_params、字段 / 单位 / 时间语义、dedup、content_hash、
                               provider mapping。只有 dataset contract 才能成为长期订阅
                               与稳定 numeric_observation 输入。
3. source inventory            prober / discover 生成的日期戳不可变快照:源里有什么表 /
                               endpoint / stream / 字段、存在性、新鲜度。是可见性,
                               不是语义承诺;可给 AI 看,不得当 dataset contract 用。
4. query template / request spec  允许执行的查询形态:绑定参数、谓词、max_rows、timeout、
                               安全规则。SQL 型走白名单模板;API / MCP 型走 endpoint
                               request spec;Lane C 的临时模板同属此类、同一 validator。
```

**登记器(registrar)唯一写 DB**:provider adapter 只返回 result 不碰库;registrar 负责
source_access、data_asset、幂等、supersede、outbox(原 F9)。

现状映射(与仓库实况一致):第 1、2 类已落地(2 个 provider catalog + 4 条 dataset yaml,
全部实测核实);第 3 类**未建**(50 表清单仅存于附录 C 文字,不可机读);第 4 类部分落地
(SQL 白名单模板现寄生于 dataset contract 的 providers 段;Lane C 临时模板将使其独立
成件)。四类是治理概念,文件形态允许演进,治理职责按四类划分。

## 6.2 多 provider 纪律

1. **dataset_key 语义命名、provider 无关**(原 F1):provider 进 provenance / catalog /
   locator / source_access,不进稳定 dataset_key。
2. **provider_priority 是服务级配置**(原 F11):不进 dataset_key、不改下游契约;
   换优先级 = 改一行配置。
3. **L1 不跨 provider 合并、不裁决**(原 F5):同 dataset_key 多 provider 各自入账
   (`(provider, dedup_key)` 唯一);冲突、采信、优先级裁决在 L2 / L3。
4. **provider 指标 ≠ 披露原始事实**(原 F2):adapter 可做字段名映射、类型规整、配置声明的
   机械单位换算,但派生指标必须带 `metric_origin` 判别,防 L2 / L3 误当披露原始值对账;
   earnings_event 与 fin_statement / fin_metric 分立(披露事件 ≠ 期间报表事实)。
5. **preflight fail-fast**(原 F12):缺表、缺列、缺 endpoint、freshness 异常、权限不足,
   必须显式 error 并列明缺什么;预检通过才允许 fetch;doctor / adapter 启动必跑。

## 6.3 幂等、去重、取代(原 F6)

semantic_key = dataset_key + 规范化 query scope;dedup_key = sha256(semantic_key ||
content_hash);`(provider, dedup_key)` 唯一。同 provider 同 semantic_key:content_hash
同 → `observed`;content_hash 变 → `materialized` + supersede 旧 active。content_hash
不含查询时间;registry 版本不进 dedup_key(版本走 provenance)。

## 6.4 安全纪律(原 F7)

SQL 只走白名单查询形态:绑定参数、allowed tables / columns、required predicates、
max_rows、timeout、deny tokens、禁 SELECT *;**只读由数据库侧强制**(只读账号 / 只读
事务),不靠 server 自律;凭证只走环境变量。方言级细则(varchar8 日期列禁 CONVERT、
篮子上限等)见附录 B.5。

## 6.5 复权与派生口径红线(原 F3)

L1 canonical 只存不复权 OHLCV + adj_factor;qfq / hfq 是派生视图且 `basis_date ≤ as_of`。
当前因子是 `latest_recomputed` 性质,**禁止当作正式回测级 as-of-safe 结果**,权益 PIT
接入后才允许升 `pit_safe`。实测硬事实:adj_factor 是 provider 相对值,跨 provider
绝对值不可比(附录 C)。

## 6.6 增量与调度

行情按交易日历驱动 security × trade_date 窗口;财务 / 事件按公告日增量 + lookback 窗口
兜重述,不按 max(report_period);载体是 source_checkpoint 增量游标表(待建)。调度形态
遵守协议 §15.7:定时批 + 手动拉起,不依赖实时在线;disclosure_anchor change feed(G1
落地后)触发同期财务拉取是跨服务联动的目标形态。

# 7. 结构化数据三条 Lane

同一账本、同一信封出口;区别只在契约状态与允许的用途。

## Lane A:注册数据集

适用:长期订阅、增量维护、进入 L2 numeric_observation 主链的数据。
要求:dataset contract + provider catalog + fixture + preflight + registrar 全链。
结果:`dataset_snapshot(contract_status = registered)`,可作为 L2 稳定准入源。

## Lane B:可发现 inventory(原 F14)

适用:让 AI / 人知道外部源里可能有什么。
要求:机器可读、日期戳、不可变快照;标明 active / stale / unknown、字段存在性、样本探测
结果、freshness 结论;由 prober / discover 现场探测生成——活库是唯一权威(附录 C
权威链),探测产物不是契约,不进 catalog 正文,不违反"不登记幽灵条目"纪律。
限制:inventory 不承诺字段语义、单位、口径、去重规则;**不能直接作为 L5 订阅源**;
AI 用到"仅 inventory 可见"的表 / 列时,字典中显式可辨"语义未核"。

## Lane C:受控 ad-hoc snapshot(原 F13)

适用:evidence_request、研究课题、人工问题中"字典可见但未注册"的一次性取数需求。
协议依据:§8.6(evidence_request)、§10.2、§6.5.1 规则 5(受控回路,产物仍先落 L1)。

形态:AI 起草 **AdhocDatasetRequest**,不是自由 SQL。请求含 source_policy、provider、
inventory_ref、table_alias / endpoint、字段、谓词、绑定参数、max_rows、timeout、用途说明;
确定性 validator 依据 provider catalog、inventory、query template 安全规则(§6.4 全套)
与 source_policy 裁决,不过即拒、报错列明;经 asset_intake 的 adapter / CLI(未来 MCP
tool)执行——查空、登记、审计自动发生;临时裸连只读库属调试行为,不产生可引用资产。

登记规则:

```text
dataset_key       = adhoc.<domain>.<semantic_slug>     # provider 无关(同 §6.2-1);
                                                        # domain 沿 dataset_key 域词表(如 cn_equity)
provider          = wind_rds / tushare_api / web_search / ...(进 provenance)
adhoc_signature   = 规范化 request spec 的哈希(同一需求可识别重复)
contract_status   = adhoc_unverified                    # 显式状态,不是缺陷伪装成正常
adhoc_status      = exploratory / promotion_required / closed
必填不降:provider / query_params / returned_fields / provider_as_of / adapter 版本(§3.7);
查空照记 source_access;动作落 action_log。字段按协议 §2.1 扩展字段纪律登记,不新增顶层对象。
```

用途边界:L2 可在一次性场景引用并完成字段映射确认;但 adhoc snapshot **不能**成为 L5
长期订阅源、不能承担自动增量、不能被当成稳定数据产品。

**晋升规则(复用即转正)**:满足任一条件,后续必须转 Lane A——同一 adhoc_signature 反复
出现;进入 L5 data subscription;需要 source_checkpoint 增量;被 L2 多次映射为同一
metric;进入正式预测流程后需持续复验。触发即置 `adhoc_status = promotion_required`;
转正动作 = 建 dataset contract + catalog 补实测 + fixture;转正或放弃后置 `closed`,
同 signature 不再允许继续 ad-hoc 执行(防长期灰色通道)。历史 adhoc snapshot 不迁移,
保持原样可追溯。

# 8. 轻载 tool_result 路径

web search、MCP、Claude / Codex、第三方插件、外部 HTTP API 的返回,先是 L1
`tool_result`,不是证据。

硬规则:

1. **agent 总结不是来源**(协议 §16.18);总结引用的网页、API 返回、搜索结果 item、
   原始片段才是来源。
2. 每个 returned_item 必带 locator;没有 locator 的结果只能留在临时上下文,不得入 L1。
3. **tool source 也 catalog 化**(§6.1 同一原则):tool 名、provider、认证 profile、
   rate limit、返回结构、locator 规则、raw 留存策略、source_tier 默认值;预检 fail-fast。
4. 弱信源(传闻 / 情绪类)默认低 tier / 低 trace(预设 Tier 3),可进冷存或待核,
   不能单独支撑正式预测(协议 §2.9)。
5. tool_result 到 L2 仍需准入,不能绕过 L2。

候选源事实与选型判据见附录 A(不排批次)。

# 9. 人工上传路径:upload_service

人工上传是 L1 中最容易污染系统的一条路径,必须从第一天按服务契约设计;它也是 L1 里
"清洗"最重的一条(OCR / 转写 / Excel 结构化),这是其独立立项的原因——**不依赖 L2 存在,
不设任何前置条件**。

硬规则:

1. **原件保真**:文件、文本、图片、音频、Excel、PPT、Word 先登记 raw_asset_ref + hash。
2. **material_type 由人显式声明**(纪要 / 调研笔记 / 数据摘录 / 计算表 / 模型工件 /
   框架建议…);L1 不靠 LLM 判定其投资语义。
3. **sensitivity 必填**:公开 / 内部 / 敏感 / 一手 / 疑似 MNPI 合规隔离;权限过滤从 L1
   public contract 开始。
4. **载体规范化**:文本切分、表格区块、OCR、转写、Excel sheet / range、公式与脚注单位保留。
5. **拿不准默认 `artifact_unit`**,由 L2 经 change_candidate / 人工裁决决定是否转证据;
   不得默认当作事实。
6. **时间语义**:event_time 用资料对应时间而非上传时间;published_at 按
   source_available_at 语义(协议 §2.5),无法证明更早可用时退化到 observed_at。

# 10. 数据目录与 AI 可读性

L1 的目录不是传统 RAG chunk 索引,而是面向 agent 的 source / asset / contract directory
(协议 §15.5:数据目录第一天建)。

目录至少暴露:

```text
sources / providers      有哪些源、凭证 profile 名、tier / trace、freshness、preflight 状态
datasets / contracts     注册数据集、字段、单位、时间语义、provider mapping、样例
inventory snapshots      源内表 / endpoint / stream / 字段、探测日期、"语义未核"标记
query templates          可执行请求形态、参数、限制、示例
assets / public views    已登记 data_asset,按 scope / time / kind / quality 过滤
source_access            查过什么、空结果、错误、provider_as_of
change feed              observed / materialized 事件
```

检索辅助字段(title / heading_path / semantic_key / keywords / retrieval_summary)只是
召回辅助,不是证据正文;L2 形成 evidence_record 必须引用原文 exact_span、表格 locator
或 record locator。

形态:近期一条 CLI 导出(契约件 + inventory 探测件);目标 MCP 包装遵守同一原则——
目录与资产读侧是 **resources**(只读),取数、上传、登记、探测是 **tools**;资源只读,
写动作一律走 tool(协议 §3.11)。字典不含凭证。

# 11. L1 / L2 边界

| 问题 | L1 | L2 |
|---|---|---|
| PDF / Excel / OCR / 转写 | 处理并形成 data_asset | 不处理 raw,收到即回流(L1_PROCESSING_REQUIRED) |
| 文档切分 | 业务结构切分,保留上下文 | 精选高价值 evidence |
| 表格结构 | 保留表头、单位、脚注、行列 locator | 抽取指标、registry 归一 |
| 结构化数据 | 查询、登记、字段契约、机械单位规整 | numeric_observation、metric mapping、采信 |
| 工具结果 | 记录 query、item、locator | 判断是否可作为证据 |
| 人工上传 | 登记、哈希、sensitivity、material_type 人声明 | change_candidate、采信 / 驳回 |
| 冲突 | 不裁决 | contested / accepted / rejected / cold |
| 预测影响 | 不判断 | 经 L3 / L5 / L6 传播 |

一句话:**L1 保证"看得见、找得到、可复查、可消费、知道是否变化";L2 才判断"这条信息
在预测系统里是什么意思"。** 两段清洗判别:L1 载体规范化对结构与载体;L2 选择性证据化
对内容语义。

# 12. 对外读契约

每个 L1 服务提供同构读契约:

1. `*_v1` public views / API;跨服务只读 public contract,不读私有表;演进遵守协议 §2.7。
2. `asset://<service>/v<n>/<kind>/<asset_id>` 稳定 URI(协议 §2.3 三条硬规则)。
3. scope keys 过滤 + 游标分页是契约义务。
4. source_ref / source_access_ref 可追溯。
5. change feed:`GET /v1/changes?after_seq` 或等价视图;事件至少区分 observed /
   materialized;单调 change_seq、at-least-once、消费端幂等、同 subject 保序(协议 §2.8)。
6. 错误码:`L1_PROCESSING_REQUIRED` / `NOT_FOUND` / `CONTRACT_VERSION_MISMATCH` /
   `GONE_SUPERSEDED`。
7. public contract 携带 sensitivity / quality_status,读侧按权限过滤。

现状(已知偏差,显式记录):读侧暂 SQL 视图;HTTP / MCP 未建;两服务的 `/v1/changes`
端点与两事件语义未落(见 §17)。

# 19. L1 硬边界(一句话,共 20 条)

1. L1 统一出口是 data_asset 信封;解决新问题先加规范 / 扩展字段,默认不新增顶层对象。
2. raw 止于 L1;L2 收到 raw 即 `L1_PROCESSING_REQUIRED` 或经 L6 回流。
3. "先轻后重"只指存储不指职责;轻存储不等于轻登记。
4. L1 只做载体规范化,不做投资语义;不得因"像套话"让实质信息对下游永久不可见。
5. 账本唯一:source_access + data_asset;禁止任何第二套 cache / 私账。
6. 查空 ≠ 错误;empty 只记 source_access 不建资产;null_observation 只在 L2 回应
   evidence_request 时生成。
7. append-only + supersede;content_hash 判变;正常消费一跳引用,审计递归全链。
8. dataset_key 语义命名、provider 无关;provider 只进 provenance。
9. L1 不跨 provider 合并、不裁决;对账采信在 L2 / L3。
10. 一切皆配置 + 预检 fail-fast;缺表缺列显式报错列明,绝不静默降级、绝不部分工作。
11. SQL 只走白名单查询形态;只读由数据库侧强制;凭证只走环境变量、不入任何配置与 locator。
12. LLM 不进登记层;LLM 出候选,确定性规则裁决(含 AdhocDatasetRequest)。
13. inventory 是探测产物不是契约;不得当 dataset contract 或 L5 订阅源使用。
14. ad-hoc 必登记、必带 adhoc_signature 与状态机;复用必转正,转正或放弃后关闭,
    不得长期滞留为灰色数据产品。
15. 复权 latest_recomputed 禁当回测级 as-of-safe;权益 PIT 前禁 qfq / hfq 正式回测。
16. agent 总结不是来源;无 locator 的 returned_item 不得入 L1。
17. 上传件 material_type 由人显式声明,拿不准默认 artifact_unit;sensitivity 必填并进
    读侧权限过滤。
18. canonical company_ref / security_ref 不可伪造;未解析用 subject_candidates 且显式。
19. 跨服务只经 `*_v1` public 契约消费;change feed 两事件语义,失效只由 materialized 触发。
20. 排程、批次、里程碑不进本协议;分步顺序由用户决定。

## B.2 端口定稿签名(冻结)

```python
@dataclass(frozen=True)
class DatasetRequest:
    dataset_key: str
    query_params: dict[str, Any]

@dataclass(frozen=True)
class ScopeHints:
    subject_candidates: list[str] | None = None
    report_period: str | None = None
    event_time: datetime | None = None
    published_at: datetime | None = None
    title: str | None = None
    semantic_key: str | None = None

@dataclass(frozen=True)
class DatasetResult:
    records: list[dict[str, Any]]
    returned_fields: list[str]
    provider_as_of: str | None
    locator: str | None      # 含 table_alias 与实际 active 物理表;严禁 host/凭证
    raw_asset_ref: str | None = None
    scope: ScopeHints = ScopeHints()
    warnings: tuple[str, ...] = ()
    stats: dict[str, int] | None = None

class ProviderError(Exception): ...

class DatasetProvider(Protocol):
    provider_name: str
    adapter_name: str
    adapter_version: str
    source_tier: SourceTier   # 首发均 tier_1
    trace_level: TraceLevel   # G1
    def fetch(self, request: DatasetRequest) -> DatasetResult: ...
```
