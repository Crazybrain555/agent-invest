# 标准化参数生成重构蓝图

## 问题分析

### 1. start_date问题
**现状：** 所有因子使用相同的start_date（表中最早数据时间）  
**问题：** 每个因子的实际最早出现时间不同，应该单独记录  
**影响：** 无法准确反映每个因子的数据开始时间

### 2. 多表处理逻辑问题
**现状：** 对每个source_table分别生成独立的标准化参数表  
**需求：** 将所有source_table的数据合并，生成一个统一的标准化参数表  
**影响：** 当前逻辑不符合用户需求，需要重构

### 3. 缺少字段冲突检测
**现状：** 没有检测多表间相同因子的冲突  
**需求：** 检测并处理(factor_name, z_windows)冲突，优先使用列表前面的表  
**影响：** 可能导致数据覆盖或不一致

### 4. 不支持无z_windows字段的表
**现状：** 假设所有表都有z_windows字段  
**需求：** 支持没有z_windows字段的表，默认window为0  
**影响：** 无法处理某些特殊表格式

### 5. 表命名逻辑需要改进
**现状：** 使用source_table名称作为前缀  
**需求：** 添加自定义table_name_prefix参数  
**影响：** 表名不够灵活

## 修改方案

### 阶段1：修复start_date计算逻辑
**目标：** 为每个因子单独计算最早出现时间

#### 1.1 修改StandardParamsGenerator类
- 添加`_get_factor_earliest_dates`方法
- 修改`_process_window_batch_vectorized`方法，记录每个因子的最早时间
- 更新结果DataFrame，包含每个因子的实际start_date

#### 1.2 验证方法
- 运行测试，检查不同因子的start_date是否不同
- 确保历史较短的因子有较晚的start_date

### 阶段2：重构多表处理逻辑
**目标：** 将多表数据合并处理，生成统一参数表

#### 2.1 修改DataPipelineManager
- 重构`run_standardization_parameter_generation`方法
- 移除分表处理逻辑，改为合并处理
- 添加`_merge_multiple_tables_data`方法

#### 2.2 修改StandardParamsGenerator
- 支持多表输入：`source_table`参数改为`source_tables`列表
- 添加表数据合并逻辑
- 保持向后兼容：单表输入自动转换为单元素列表

#### 2.3 验证方法
- 测试单表输入，确保行为不变
- 测试多表输入，确保数据正确合并

### 阶段3：添加字段冲突检测
**目标：** 检测并处理多表间的字段冲突

#### 3.1 实现冲突检测
- 在`_merge_multiple_tables_data`中添加冲突检测
- 记录冲突的(factor_name, z_windows)组合
- 输出warning信息，说明冲突处理策略

#### 3.2 冲突处理策略
- 优先保留列表中前面表的数据
- 记录被丢弃的数据来源
- 在最终结果中添加数据来源标识

#### 3.3 验证方法
- 构造有冲突的测试数据
- 确认warning正确输出
- 验证优先级处理正确

### 阶段4：支持无z_windows字段的表
**目标：** 兼容没有z_windows字段的表格式

#### 4.1 表结构检测
- 添加`_check_table_structure`方法
- 检测表是否包含z_windows字段
- 为无z_windows字段的表添加默认值0

#### 4.2 数据处理适配
- 修改`_get_feature_combinations`方法
- 修改SQL查询逻辑，兼容两种表结构
- 确保窗口为0的因子正确处理

#### 4.3 验证方法
- 测试有z_windows字段的表（正常情况）
- 测试无z_windows字段的表（特殊情况）
- 确保两种情况都能正确处理

### 阶段5：改进表命名逻辑
**目标：** 添加自定义表名前缀参数

#### 5.1 添加新参数
- 在StandardParamsGenerator构造函数中添加`table_name_prefix`参数
- 默认值为"multi_table"（多表）或source_table名称（单表）
- 更新表命名逻辑

#### 5.2 向后兼容
- 单表输入时，如果未指定prefix，使用原有逻辑
- 多表输入时，必须指定prefix或使用默认值
- 保持现有调用代码的兼容性

#### 5.3 验证方法
- 测试默认命名行为
- 测试自定义prefix
- 确保表名唯一且有意义
