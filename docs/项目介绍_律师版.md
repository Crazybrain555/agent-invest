# A股量化投资深度学习预测系统技术说明

## 1. 项目概述

本项目是一个完整的人工智能量化投资系统，专门针对中国A股市场开发。系统的核心目标是通过深度学习技术，从海量、高频的金融市场数据中自动学习并挖掘有效的预测信号（Alpha因子），构建能够在真实市场环境中获得超额收益的量化投资策略。

该系统解决了金融数据普遍存在的四大技术挑战：
- 高维度特征空间：处理数百个不同类型的金融因子
- 高噪声环境：金融数据信噪比极低，需要强大的降噪能力
- 非平稳性：市场环境持续变化，数据分布随时间漂移
- 强时序依赖：股价变动具有复杂的时间序列特征和长期记忆效应

为应对这些挑战，我们构建了一个端到端的自动化系统，包含从原始数据处理到模型训练、再到策略回测的完整工作流程。

## 2. 系统架构与数据流程

### 2.1 整体架构设计

系统采用分层解耦的模块化架构，确保各组件可独立开发、测试和部署：

```
原始数据源 → 数据处理管道 → 特征工程 → 模型训练 → 策略回测 → 实盘部署
    ↓           ↓           ↓         ↓         ↓         ↓
 Wind/聚源    因子构建     深度学习    TSViT模型   量化策略   自动交易
 网络数据    标准化处理    特征提取    位置编码    风险控制   绩效监控
```

### 2.2 数据处理管道

#### 2.2.1 多源数据接入系统
系统支持多种数据源的统一接入：
- Wind数据库：接入中国A股日行情数据表（AShareEODPrices），包含复权价格、成交量、换手率等基础市场数据
- 聚源数据库：补充基本面和宏观数据
- 量化投资部私有数据：通过网络共享目录（`\\space\signal`、`\\space\forbid`）获取600+个专有因子和禁投池数据
- 本地测试数据库：TDSQL数据库（ai_is Schema），存储处理后的训练数据

#### 2.2.2 因子工程流程
系统实现了基于经济学原理的分类因子工程方法：

第一阶段：因子分类与归一化
- 价格类因子：adj_close、adj_open、adj_high、adj_low、vwap等
  - 处理方法：统一以adj_close为分母进行归一化，结果取对数
- 体量类因子：volume、amount、成交额、资金流等
  - 处理方法：以自身历史均值为分母归一化，结果取对数
- 比例类因子：turnover_rate、swing、各类比率指标
  - 处理方法：window=0时保留原值，其他窗口按体量类处理
- 状态类因子：up_down_limit_status、trade_status等
  - 处理方法：仅允许window=0，保持离散状态值

第二阶段：多窗口特征构建
- 自动为基础因子生成多尺度窗口（如1/30/60/90天等），系统性捕捉不同时间尺度的规律；窗口规范与命名通过 `src/data_service/pipelines/Dataset_builder/factor_windows.py` 统一管理。

第三阶段：时序滞后特征
- 针对训练序列长度（如T=300），按统一键（股票-日期）构建可流式生成的序列样本。

#### 2.2.3 标准化与缺失值处理
系统采用两阶段标准化策略：
1) 历史统计标准化：基于2008-2018年的历史数据计算每个因子的均值、标准差和MAD边界；
2) 日期内标准化：对每个交易日内的因子值进行截面标准化，消除不同时期的尺度差异。

缺失值处理采用因子类别差异化策略：
- 价格类因子：保持NaN，由后续流程自动过滤
- 成交量类因子：填充0（表示无交易）
- 财务类因子：前向填充+行业中位数填充
- 状态类因子：前向填充+行业中位数填充

### 2.3 标签构建系统

系统实现了基于相关性平滑的标签构建方法：

第一步：原始收益率计算
```
label_raw = adj_close[t+label_shift+1] / adj_close[t+1] - 1
```
其中label_shift=10，即预测未来10个交易日的累计收益率。

第二步：历史相关性计算
- 对每个交易日，计算向前240天的股票间Spearman相关性矩阵，识别每只股票的前K个最相关邻居。

第三步：相关性平滑标准化
```
label_adj = (label_raw - mean(top_neighbors)) / std(top_neighbors)
```
目标：降低个股特异噪声、提高标签稳定性、保持横截面排序关系。

## 3. 核心深度学习模型：TSViT Transformer（当前主力）

### 3.1 模型整体架构

TSViT 采用“Patch-Embed → Transformer 编码器 → 稳定输出头”的结构，针对高噪声金融时序做了稳定性增强：

```
输入[B,T,D] → Patch-Embed(Flatten P=5,S=5, Dh=64)
           → Position Encoding(默认: Sinus)
           → Transformer Encoder(6层, 4头, PreNorm, Dropout/AttnDropout)
           → 稳定输出头(cosine_mean) + 预测归一化(BatchNorm1d)
           → 预测[B]
```

其中：T=序列长度（默认300，对齐索引lag），D=特征维度（自动推断），Dh=隐藏维度（64）。

### 3.2 关键组件与实现

- Patch-Embed（flatten）
  - 将 [B,T,D] 滑窗分块为 tokens，并映射到 Dh 维；P=5，S=5。
  - 支持可切换的嵌入实现：flatten / separable_linear / separable_conv / multiscale_sepconv。
- 位置编码（Position）
  - 默认 Sinus，可选 Abs/RoPE/RPB/RoPE+RPB；RoPE/RPB在高噪声长序列下更稳健。
- 编码器（Encoder）
  - 6 层 Transformer，4 头注意力，PreNorm，dropout=0.2，attn_dropout=0.1。
  - 自适应实现：无RoPE/DropPath时走原生Encoder，启用高级特性时走自定义实现。
- 输出头（Head）
  - 采用 cosine_mean 稳定头，跨token求稳定聚合，配合 BatchNorm1d 进行横截面预测归一化（不学习参数、无running stats）。
- 正则化
  - 支持 TokenDrop、DropPath（当前默认关闭）以增强泛化。

### 3.3 损失与优化

- 排序主导的横截面相关损失（wIC，相关系数模式）
  - wic_mode=corr，关注预测与标签的横截面相关性；
  - 支持稳健项（Huber，delta可调）与分位偏置（tau）调节，提升抗异常能力；
  - 当前默认关闭正交惩罚（可按需开启，alpha_corr可调）。
- 优化与调度
  - 优化器：AdamW；学习率=4e-5，权重衰减=1.0；
  - 调度器：线性预热(5 epochs) + 余弦退火(min_lr=1e-6)；
  - 梯度裁剪：1.0；混合精度：AMP 默认开启。
- 参数分组
  - 对注意力、头部、Patch-Embed组分别设置较弱的相对WD因子，兼顾主体与边缘模块的正则强度。

### 3.4 训练与数据加载（DuckDB Streaming）

- 训练入口：
```
python run_tsvit.py --config configs/models/transformer/tsvit.yaml --dataset data/Dataset/pv_v7
```
- 数据加载：DuckDB + 宽表流式IterableDataset（mirror ring buffer），CPU端NumPy批组装、一次性H2D拷贝；
  - `chunk_size` 控制每步样本数（默认4096）；
  - `batch_by` 支持 `chunk`（默认）与 `date`（逐日批次，便于横截面IC评估）；
  - TwoStagePrefetcher：`cpu_queue_size` 控制CPU预取深度；
  - I/O half：`io_half=true` 时启用H2D半精度传输，显著降低带宽占用；
  - DuckDB资源：`duck_threads/memory/cache/temp_directory` 可在YAML中统一配置。

## 4. 数据集构建系统（pv_v7 Wide+Streaming）

### 4.1 目录结构与元数据

- 根目录：`data/Dataset/pv_v7`
- 宽表分片：`shards/wide_daily/year=YYYY/part-*.parquet`
- 标签分片：`shards/labels/year=YYYY/part-*.parquet`
- 统一索引：`meta/indices/index_lag{T}.parquet`（如 T∈{30,300,500}）
- 数据切分：`meta/splits.parquet`（train/valid/test 时间段切分）
- 模式说明：`meta/schema.json`（特征清单、标签列、索引路径等）

### 4.2 构建与初始化

- 构建脚本：`initiate_pip_pv_dataset.py`
  - 调用 `build_pv_dataset_wide_daily(...)`，按季度分块（`chunk_freq='Q'`），暖启动 `warmup_days=200`；
  - 统一写入 schema、splits，并生成 indices（默认滞后窗口 `lags=(30,300,500)`）；
  - 过滤规则：支持禁投池、代码前缀过滤、restricted因子屏蔽等；
  - 单批因子上限（pivot 降内存峰值）：`max_factors_per_batch=16`。
- 索引工具：`tools/generate_indices.py` 可独立重建索引与split索引。

示例（生成索引）：
```
python tools/generate_indices.py --dataset-root data/Dataset/pv_v7 --lags 30,300,500 --threads 6
```

### 4.3 多表融合与特征窗口

- 多表融合：来自市值/情绪/成长/分析师/价值/质量/另类等多张 `ai_is.quantitative_*` 与市场基础表；
- 窗口规范：使用 `src/data_service/pipelines/Dataset_builder/factor_windows.py` 统一定义窗口与命名；
- 标签：默认 `tc_t10_n30_adj`（lead=10，含稳健平滑处理），来源 `ai_is.training_label_v1`；
- 分割：
  - 训练：2008-2018
  - 验证：2019-2021
  - 测试：2022-至今（配置可调整）。

### 4.4 数据质量

- 连续缺失检测、MAD 异常裁剪、标签可用性标记（`has_label`）；
- 统一键（`trade_date, stock_code`）与 `ok_factors` 标记，保证批次特征完整性；
- 训练索引默认要求 `has_label=1`，评估/推理放宽以覆盖更多样本。

### 5.2 交易策略实现

#### 5.2.1 组合构建
- 选股策略：基于模型预测分数选择前N只股票（默认100）
- 权重分配：等权或规则权重（支持行业/市值中性化）

### 5.3 评估指标

## 7. 技术创新总结

### 7.1 数据处理层面的创新

1) 分类因子工程：按价格、体量、比例、状态等类别进行差异化处理，保留经济学含义。
2) pv_v7 Wide+Streaming：宽表分片 + 统一索引 + 流式滑动窗口生成，提高规模化与稳定性。
3) 相关性平滑标签：基于历史相关邻居进行平滑，降低标签噪声、提升稳定性。

### 7.2 模型架构层面的创新

1) TSViT 时序Transformer：Patch-Embed + 多位置编码（Sinus/Abs/RoPE/RPB），兼顾长序列记忆与噪声稳健性。
2) 稳定输出头 + 预测归一化：cosine_mean 头结合横截面 BatchNorm1d，显著提升分布漂移下的稳定性。
3) 排序主导损失：以 wIC（corr）为核心，叠加稳健Huber/分位偏置，贴合选股排序目标。

### 7.3 系统工程层面的创新

1) DuckDB 流式数据与镜像环缓冲：将窗口展开从SQL侧下沉到NumPy矢量化，显著降低CPU消耗与内存峰值。
2) 端到端自动化：从数据获取到模型训练再到回测验证的全流程自动化，提高研发效率与可靠性。
3) 索引与切分标准化：统一的 indices/splits/schema 元数据，便于可重复与可扩展。

### 7.4 性能优化创新

1) 混合精度训练：AMP 提升训练吞吐并降低显存占用。
2) 渐进式数据流：DuckDB 流式+mirror ring buffer，将窗口展开从SQL下沉到NumPy矢量化，CPU开销可控。
3) I/O 优化：PinnedMemory + 半精度 H2D 传输，缓解PCIe带宽瓶颈； `duck_threads/memory/cache` 可按机器级别调优。

## 8. 系统性能表现

### 8.1 预测性能

- 关注横截面信息系数（IC）水平、稳定性（胜率/分布）与跨周期一致性；
- 采用严格的时间分割与“训练/验证/测试”评估，避免未来信息泄露。

### 8.2 投资绩效

- 在严格的时序分割与成本设置下进行评估，关注稳定的横截面排序能力与风险调整收益；
- 具体数值依赖于选用的特征集、训练窗口、成本/滑点参数与回测区间，详见回测报告。

### 8.3 系统效率

- 数据处理：宽表分片 + DuckDB 流式，TB级数据处理时间显著缩短

- 内存使用：通过分块/索引与矢量化环缓冲控制峰值内存
- 自动化程度：从数据获取到回测报告的全流程自动化

### 8.4 技术指标

- 模型复杂度：百万级参数量，兼顾精度与效率

- 系统可用性：7×24小时稳定运行
