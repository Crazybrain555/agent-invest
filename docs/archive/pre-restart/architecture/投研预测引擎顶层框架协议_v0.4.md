先给整体判断:v0.3 的骨架成立,层与流程的划分可以锁。但它有一个结构级缺口和三个归属不清——缺口就是你最后那条批注指出的:整个系统只有"推"(数据流入→向下传播),没有"拉"(从研究目标出发主动找数据),冷启动和新增个股在这个框架里没有位置;归属不清是:口径契约、对账规则这类"行动的方法"没有统一的家,调度脊柱缺"行动"这个概念,知识层"可训练"没有落地机制。这四个问题相互关联,可以用同一组改动解决。下面先给解决办法,再给 v0.4。

## 一、解决办法

**1. 口径契约、对账规则放哪(你在第 1 节和第 5 节的批注,一起回答)**

你的直觉对了一半:系统确实需要一批"行动的方法"——清洗规则、抽取重点、对账规则、仲裁原则、口径契约、课题模板,都是 skill 性质的东西,有共通部分也有逐股部分。但它们不该放进调度层。区分三个东西:**规则**(内容,声明性,要版本化、要人批、要进血缘)、**行动**(执行过程)、**调度**(何时执行什么)。调度必须薄且确定,十年不改;规则会频繁演化。把规则塞进调度,版本管理和血缘挂靠全乱。

所以方案是:旁路层扩成**知识与规则层**,内设两个架——**框架架**(怎么理解:行业框架、模板树、动机透镜……)和**规则工件架**(怎么操作:清洗规则、对账规则、仲裁原则、口径契约、课题模板)。两架维护方式完全相同:条目化、版本化、人批、进血缘。调度的行动在执行时**加载**对应规则工件——调度是演奏者,规则是乐谱。放一起还有个额外理由:你要的"可训练大脑"的训练对象恰恰就是框架条目+规则工件,它们本来就该是同一个语料库。

口径契约归入规则工件架,但因为它被数据(derived claims)和预测公式直接引用、升版触发重算,保留单独命名和"三处同引"硬规则。结构 = 全局基准 + 公司附录(逐家叠加),v0 占位即可,符合你的批注。

对账同理拆三块:Tier 分级是 L1 的元数据;对账关系、容差、置信度衰减函数是**对账规则工件**;对账检查是入库流程和变更传播流程里的**标准行动步骤**。采纳你的连续衰减想法:容差带内一致则加分,带外按偏差幅度降置信,超限转 contested。第 5 节作为独立章节消失。

**2. 知识层作为"可训练大脑"(第 7 节批注)**

先认账:你对"主要玩家"的质疑成立,我上一版"玩家名单放框架层打事实标签"是错的。按我们自己的判别标准,玩家、份额、供应关系随数据流入而更新、有来源、会冲突——这是 claim 的全部特征。修正:**供应商、客户、产业链归属、竞争关系作为"关系型 claims"进证据账本**;框架层只放结构模板("这个行业分哪些环节、格局演变看什么变量");"当前玩家地图" = 模板 × 关系 claims 的派生视图。边界从此干净。

可训练的问题,结论是:**不需要重排架构,需要补三个机制**,其中一个必须现在就定:

- **条目级引用**:预测快照不能只记"框架层版本号",要记到具体条目 ID(用了哪个行业模板 v 几、哪条动机透镜)。否则误差归因到不了条目,"反向传播"没有路径。
- **按时点重放(as-of)**:账本和快照必须支持"回到 T 时刻的状态"——给定当时的 claims 和契约,换一版框架条目,重算预测,和实际比。append-only 设计天然支持,但查询语义要第一天定,补造的代价是重写存储。这条进硬边界。
- **框架演进流程**:归因→定位条目→diff 提案→历史重放评测→人批晋级。

对应你的神经网络类比,映射是:前向 = 框架+数据→预测;loss = 财报误差;反传 = 逐节点归因到所引条目;梯度更新 = 条目 diff;冻结层 = 硬边界与调度;可训练参数 = 框架条目 + 规则工件 + 契约公司附录 + 托底规则。训练形态分阶段:现在是版本化文本的人审迭代,数据够了改自动重放评测筛 diff,远期才谈以 L3+归因日志为语料的微调——三个阶段架构是同一套。

还有一个统计上的关键点:每家公司每年只有 4 个财报验证点,200 家约 800 个标签/年,逐家学习样本太稀。**条目跨公司共享是统计功效的唯一来源**——一条行业模板被 20 家引用,它的"梯度"来自 20 家的误差。所以设计原则:行业共性尽量进共享模板条目,公司特例才进公司附录,能不分叉就不分叉。

**3. 调度脊柱 = 感知 / 触发 / 准入 / 行动 / 队列(第 9 节三条批注)**

采纳你的"感知—触发—行动"三分,补两件成五件。你说 GPT 版缺"行动",对,这是那一节最大的洞:

- **感知**:最小血缘集 + 订阅索引。回应你"不能太重":第一天只建四类边——claim→假设、契约→derived claims 与公式、框架条目→驱动树与假设、假设→快照——这四类正好覆盖你说的目的(改了数据/框架/claims,快速找到谁受影响、谁要重算)。其余依赖不单独建图:每个行动在 M-LOG 里记输入输出,引用关系自然留存,索引将来按需补。"信息单元"降级为 claim 的来源指针(文档 ID+段落位置),不做独立节点;"框架→驱动树"这条边的意思就是"这家公司的树是从哪个模板实例化的"。你说"财报披露→复盘结果"不算血缘,同意——那是日志记录,删。
- **触发**:事件、定时、**人工**三类,人工是一等触发源且直通(不过准入)。
- **准入(原"重要性闸门")**:你说"可能不是那么回事"——如果你的意思是它不该是个独立组件,同意。它只是触发与行动之间的一条准入策略,作用就两个:控成本(不是每条微信都值得跑一遍传播,token 和你的注意力都是钱)、可审计(为什么算了/没算,事后要能查)。形态:对每个候选行动算重要性分(规则特征为主:Tier、偏离幅度、临近财报、波及公司数;定性内容可以让 LLM 打分,但**只作为特征之一**),确定性映射到{立即执行 / 低优先入队 / 仅记录 / 转人工}。
- **行动库**:原子行动(轻处理、抽取、校验、对账、重算节点、生成待办、归档)+ 复合行动(课题、个股初始化、财报季复盘)。每个行动声明输入输出(供日志和血缘)、加载所需规则工件、可由 agent 或确定性代码执行——正好覆盖你说的"行动可能是 agent,也可能是函数参数更新重算"。
- **失效队列**:不变。

**4. 课题:把"拉"补进框架(你最后的大批注)**

这个缺口是结构级的,但解法不需要第二个框架:**课题 = 调度行动库里的一类复合行动**。定义:课题 = {绑定的目标变量(某公司某 driver,或阻塞预测的某个框架空缺)+ 触发来源 + 信息需求清单 + 子课题 + 产出}。

执行循环,以"旭创某产品毛利"为例:立题(框架模板生成该问什么:原材料成本、良率、工艺、价格)→ 先查证据账本和冷存(复用已有)→ 缺口发起**主动获取行动**(web 检索、论文 API、官网、券商库、MCP)→ **所得材料一律走标准入库带进账本**,不走旁门——这是关键,保证课题学到的东西被存档、被血缘、可复用 → 仍缺则生成人待办(问卖方、专家、调研)→ 信息够了更新假设/树节点,或提框架 diff 人批 → 必要时开子课题。课题有预算:递归深度、子课题数、检索轮次设上限,和情景分支同理防爆炸。结案记录进 M-LOG:产出了哪些 claims、假设、框架条目,残留缺口转冷存或长期待办——这些结案记录将来也是训练语料。

由此:**新增个股 = 一个标准化的最大课题**(初始化课题模板:业务与产品拆分、收入结构、上下游与供应商、产能扩产、竞争格局、技术路线、价格毛利结构、大客户、激励与诉求、历史财务重构;每项落为子课题或暂用托底),产出 = 能出影子预测的最小模型。成熟期的被动数据流和建设期的课题驱动,是**同一套机械的两个方向**:推 = 数据到→传播→必要时提案课题(人批);拉 = 课题→检索→入库→更新。两个方向在证据账本汇合,共用入库带和调度。你要求"围绕目标",落在硬规则上:课题必须绑定目标变量,禁止"研究一下某行业"式立题;行业级课题也要锚定"它阻塞了哪些公司的预测"。

**5. 溯源降级(批注末尾)+ web 来源分级(第 2 节批注)**

接受现实,但分级降,不一刀切:**Tier 0 锚必须存原文**(公告 PDF 从巨潮拿,成本极低,这是验证和对账的根,不能省);其余来源至少存"来源标识 + URL + 访问时间";存不下原文的 claim 打"弱溯源"标、置信度封顶;归档器留接口以后补。另外检索行为本身要记日志——**查过但没查到,也是信息**:避免重复检索,且自动转待办候选。

web 来源不按"web"一刀切,按发布主体分级:官网公告/监管渠道 = 0A;官网其他材料、业绩说明会 = 0B;政府统计、协会 = 1;权威财经媒体与深度报道 = 2;**新增 Tier 3:自媒体、评论员、大 V、论坛**——只进弱信号池或作印证,不能单独成为采信依据。论文和技术资料特殊:多数不产 claims,而是作为框架架(技术路线条目)的提案材料,走人批通道。

**6. 小项**:baseline claims 一阶段删除,流程里留槽位,以后想比一致预期再启用(采纳);claim 状态枚举标为模块级,框架级只锁"状态机必须存在"(采纳);契约全局+附录(采纳,见第 1 条)。

## 二、框架协议 v0.4

### 0. 系统边界

系统唯一正式产出:公司未来财务预测。当前对外输出:契约口径下的未来季度/年度净利润(契约 v0=原始财报口径,v0.1=+扣非,后续叠加公司附录)。

不做:估值、选股、买卖建议、便宜判断、组合构建。

内部必须保留:利润桥、现金质量检查、关键假设、证据版本、契约版本、框架条目引用、模型版本、中间计算节点、模型工作底稿、冲突状态、情景分支、预测区间、敏感变量、正式与影子快照、课题记录、检索记录、财报季复盘结果。

### 1. 总体形态

- **双向主管道**。推:原始资料层 → 入库处理带 → 证据账本 → 个股预测层 → 预测快照。拉:课题 → 查账本/主动获取 → 入库处理带 → 证据账本 → 更新假设/树/框架。两个方向共用账本、入库带与调度。
- **旁路:知识与规则层**,两个架:框架架(解释结构)、规则工件架(操作规则,含口径契约)。
- **调度脊柱**:感知 / 触发 / 准入 / 行动 / 队列。
- **两条记录线**:执行日志(append-only)、人机待办。
- **四个标准流程**:入库、变更传播、课题、财报季复盘。

### 2. 原始资料层

双通道:被动投喂(微信、研报、纪要、券商库、人工上传)与主动获取(web 检索、官网、论文 API、MCP、券商 API)。主动获取所得同样登记入本层。

来源分级:
- **Tier 0A 硬披露锚**:财报、业绩预告/快报、正式公告、问询函回复。原文必存。
- **Tier 0B 软披露锚**:投关活动记录、业绩说明会、官网材料、公开路演。
- **Tier 1 结构化外部数据**:券商库、协会、海关、政府统计。
- **Tier 2 外部研究与观点**:研报、纪要、专家访谈、权威媒体深度内容。
- **Tier 3 弱公开信源**:自媒体、评论员、大 V、论坛。只进弱信号池或作印证,不单独成为采信依据。
- **Tier F 自有一手**:调研、专家交流、路演笔记。高价值不天然高信任,置信取决于可复核性与锚一致性。

溯源规则:0A 存原文;其余至少存来源标识+URL+时间;弱溯源 claim 置信封顶;归档器留接口。检索行为入日志,"查过未得"记录并可转待办。

硬规则:原文不可覆盖,只追加;纠错以新版本进入。轻处理规则优先(去重、时间、类型、代码匹配、事件分类、切分);LLM 只做实体消歧、复杂切分、模糊主体、初步摘要。论文/技术资料默认路由为框架架提案材料,不直接产 claims。

### 3. 入库处理带

按信息单元处理。职责:抽取、主体/时间/指标/事件判定、新旧判断、去重、冲突检测、**锚定对账检查(加载对账规则工件)**、可信度初评、重要性评分、定性信息向 driver 初步映射、分流。

四个去向:证据账本 / 冷存弱信号池 / 人机待办 / 丢弃。

agent 角色:生产、校验、冲突、重要性。校验隔离:校验只见原文与产出,不见生产推理。本带降噪、显化冲突、标注置信,不判真伪;真伪三道防线 = 账本采信排序、人裁决、财报证伪。

### 4. 证据账本

基本单位 claim:{主体、指标/事件、陈述或数值、单位、口径标签、时间范围、性质(事实/观点/估算/预测/传闻)、来源链、Tier、溯源等级、置信度、冲突状态、采信状态、下游引用}。

三类内容:
1. **原始 claims**:全来源并列,含**关系型 claims**(供应商、客户、产业链归属、竞争关系、份额)。
2. **当前采信 claims**:状态机必须存在;状态枚举(accepted/pending/contested/rejected/archived/provisional/scenario-set)为模块级,可调。
3. **derived claims**:由原始 claims 经契约或计算规则生成;逻辑上属账本,可缓存,不得成第二套真相。

对账规则:外部细分数据须与披露锚解释得通;容差带内一致加置信,带外按偏差幅度衰减,超限转 contested、倾向硬锚、生成待办、必要时情景化。软锚提升置信但不压倒一切。

账本与快照支持按时点(as-of)重放查询。

### 5. 知识与规则层(旁路)

**框架架**(解释结构,条目化、版本化、按条目 ID 被引用):行业研究框架、产业链结构模板、行业驱动因子模板树、商业模式、技术路线、政策解读方法、治理与动机透镜、财务预测模板、三大表建模规则。玩家地图不在此存储,为"模板 × 账本关系 claims"的派生视图。

**规则工件架**(操作规则,同样条目化、版本化,被调度行动加载执行):清洗与抽取规则、对账规则、冲突仲裁原则、课题模板、行动手册、**口径契约**。

口径契约:全局基准 + 公司附录;每条政策 = 文字理由 + 可执行规则,引擎只执行规则段;历史重构、预测公式、财报复盘三处同版引用;升版触发历史重算与相关模型重估;复盘优先用快照当时版本,升版后可补做重述复盘但不覆盖原结果。

判别标准:账本装"关于世界的陈述",本层装"理解陈述的结构与操作的规则";随数据流入更新的归账本,随认知演进更新的归本层。

演进机制(可训练性):预测快照记录所引条目 ID;误差归因落到条目;diff 提案(人或 agent)经历史重放评测、人批晋级;行业共性优先进共享模板条目,公司特例进附录,为评测聚样本。核心框架变更必须人批,变更进血缘、触发引用公司重检。

### 6. 个股预测层

每公司一个预测对象:

1. **驱动树**:由行业模板条目实例化。利润表全科目在勾稽结构内生成(收入→成本→毛利→费用→经营利润→利润总额→所得税→少数股东损益→归母净利润);未研究科目用托底规则(历史比率/趋势/行业均值/人工假设),不可跳过。现金质量 driver(应收、存货、合同负债、经营现金流、资本开支、折旧、减值)与同一棵树联动。三大表演进 = 逐步把托底规则替换为研究化 driver;勾稽靠构造。
2. **数据绑定与订阅**:绑定键 = 主体 × 业务/产品/客户/区域 × 指标/事件 × 期间 × 口径 × 来源优先级;注册订阅供路由。
3. **假设账本**:假设值、期间、来源(claims/锚/外部研究/人工)、契约与框架条目引用、置信度、冲突状态、下次验证点。点值或情景分支;分支仅限高重要性 contested driver,数量受限,主预测用当前采信值,分支供区间与敏感性,分支利润差计入待办优先级。
4. **工作底稿与快照**:底稿存输入版本、中间节点、利润桥、各项拆分与假设说明、排除证据的原因、人工覆盖记录。快照发布后不可回改,含四版本引用、条目引用、全部关键中间节点、输出、区间、置信度、敏感变量、最脆弱假设、污染标记、活跃分支。影子常算;正式过闸,高重要性冲突未决阻塞正式不阻塞影子。

### 7. 调度脊柱

- **感知**:最小血缘集四类边(claim→假设;契约→derived claims 与公式;框架条目→驱动树与假设;假设→快照)+ 订阅索引;其余依赖由行动的输入输出日志留存,索引按需建。
- **触发**:事件(新资料、新 claim、状态变化、人工裁决、契约升版、框架变更、财报披露)、定时(冷存扫描、模型陈旧、假设过期)、人工(直通,不过准入)。
- **准入**:对候选行动算重要性分(确定性特征为主,LLM 评分仅作特征),确定性映射到{立即执行/低优先入队/仅记录/转人工}。
- **行动库**:原子行动(轻处理、抽取、校验、对账、重算、生成待办、归档、检索)与复合行动(课题、个股初始化、财报季复盘)。每个行动声明输入输出、加载所需规则工件、由代码或 agent 执行、写日志。
- **失效队列**:标记受影响对象 → 准入分级 → 入队 → 自动重算/影子重算/请求人工/仅观察 → 新快照。

### 8. 研究课题(拉式回路)

课题 = 复合行动,必须绑定目标变量(某公司某 driver,或阻塞预测的框架空缺)。

触发来源:人工立题;模型缺数据或低置信;高重要性冲突;弱信号累计;个股初始化;数据流提案(现阶段人批准)。

执行循环:立题与信息需求清单(由框架模板生成)→ 查账本与冷存 → 缺口发起主动获取(所得材料一律经入库带入账本)→ 仍缺转人待办 → 更新假设/树节点或提框架 diff(人批)→ 必要时开子课题。

预算约束:递归深度、子课题数、检索轮次设上限。结案记录入日志:产出 claims/假设/条目清单 + 残留缺口去向。

个股初始化 = 标准化最大课题:业务与产品拆分、收入结构(产品/客户/区域)、上下游与供应商、产能与扩产、竞争格局与份额、技术路线、价格与毛利结构、大客户依赖、激励与业绩诉求、历史财务重构;每项落子课题或托底;产出 = 可出影子预测的最小模型。行业级课题须锚定其阻塞的公司预测,产出以共享框架条目为主。

### 9. 标准流程

1. **入库**:落库登记 → 轻处理 → 抽取 → 校验隔离 → 冲突与对账检查 → 准入 → 账本/冷存/待办/丢弃。
2. **变更传播**:claim/契约/框架/裁决变化 → 订阅与血缘定位 → 准入 → 失效队列 → 重算/影子/派单 → 新快照。
3. **课题**:见第 8 节。
4. **财报季复盘**:财报与公告入库(锚)→ 对账冲账本 → 按快照当时契约重构实际值 → 逐节点对比利润桥、定位首个偏离节点 → 误差归因(来源错/抽取错/口径错/锚理解错/仲裁错/假设方向错/假设节奏错/模型结构错/框架条目错/人工覆盖错/突发事件/蒙对逻辑错)→ 回写来源可信度、规则工件、契约、框架条目、个股模型、待办优先级。(一致预期对比为可选槽位,启用后加入。)

### 10. 冷存/弱信号池

收纳单条不足以行动但可累计的信息。触发:同主体同指标同方向累计超阈;相关 driver 转 contested;新锚或新证据激活;定期扫描发现趋势。触发后重入入库带或账本,**或提案课题(人批)**。

### 11. 人机待办

排序 = 预测影响 × 置信度缺口 × 财报临近度 × 可解决性 × 分歧价值(情景分支净利润差)。待办落到变量级。课题的审批与进展同在此面板。人的每次裁决记录:结果、理由、所用资料、是否覆盖机器判断、影响哪些假设、是否触发重算——回流为规则与框架优化输入。物理感知任务(调研、专家、路演)为人独有。

### 12. 运行形态

按事件语义设计,以定时/人工拉起的 session 式批处理运行:每次运行识别新增、补触发、传播失效、重算影子、生成待办、必要时出正式快照。任何机制不得隐性依赖实时在线。控制逻辑放在规则文件、框架文件、契约文件、底稿约定中,不绑定特定 harness 专有能力。

### 13. 硬边界(锁定)

1. raw 不可覆盖,只追加;纠错以新版本进入。
2. 事实、观点、估算、预测、关系、口径、框架、规则、假设、输出分开存放。
3. 知识与规则层是旁路;框架与规则工件分架,均条目化、版本化、按条目被引用。
4. 溯源分级:0A 原文必存;其余至少来源标识+时间;弱溯源置信封顶。
5. 披露为锚,分硬软;外部细分须与锚解释得通,置信随偏差衰减,超限转 contested。
6. 口径契约第一天存在,可极轻;全局基准+公司附录;引擎只执行规则段。
7. 历史重构、未来预测、财报复盘共用同版契约;复盘优先用快照当时版本。
8. derived claims 属账本,不得成第二套真相。
9. 快照必须保存四版本、条目引用、中间节点与工作底稿。
10. 净利润阶段必须有完整利润桥与现金质量联动 driver;勾稽靠构造。
11. 冲突不吞:保留、打标、传染;高重要性冲突阻塞正式不阻塞影子;情景分支限高重要性 contested 且数量受限。
12. 低影响信息进冷存;冷存必须有触发机制。
13. 生产与校验分离;校验只见原文与产出。
14. 凡可确定性完成不交 LLM;触发、准入、传播为确定性规则,LLM 评分仅作特征。
15. 调度 = 感知/触发/准入/行动/队列;血缘按最小集建,其余靠日志引用。
16. 上游变化经订阅与血缘局部重算,不全量。
17. 课题是复合行动,不是新层;必须绑定目标变量;递归与检索有预算;产出一律经入库带入账本。
18. 主动获取与被动投喂同道入库;检索未得也记录。
19. 账本与快照支持按时点重放;框架演进以重放评测+人批晋级。
20. 行业共性进共享模板条目,公司特例进附录。
21. 财报季复盘是流程不是层;必须逐节点对比并归因、回写上游。
22. 一致预期 baseline 为可选模块,未启用不进系统。
23. 系统不做估值、选股、买卖建议。
24. demo 期运行为定时/人工拉起批式;控制逻辑 harness 无关。
